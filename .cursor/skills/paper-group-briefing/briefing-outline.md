# 六问展开（给模型用的拆解，不替代用户原话）

用户原话在 `SKILL.md` 里逐字保留。这里只把每一问拆成必须写全的子条，避免漏项。

## 问 1 — 任务 / 问题 / motivation / 局限 / 例子

写清四层，不要互相替换：

1. **任务**：输入、输出、训练阶段（预训练 / SFT / RL / 蒸馏）、部署时谁在生成。
2. **问题**：现有管线在什么条件下失败（师生差大、长上下文、特权文风、无界 log-ratio…）。
3. **Motivation**：失败的机制原因（mode-seeking、exposure bias、稀疏奖励、分布偏移），尽量落到一个公式或复杂度。
4. **现有方法局限**：列 3–8 个对照族，每行「作用位置 + 为何不够」。必须能对上后文模块（模块 A 就是为了堵局限 A）。
5. **例子**：具体数字或短序列。先演示旧方法错，再点出本文切口。禁止只有口号没有数。

## 问 2 — 为什么是这些工具；模块树；交互

先答「为什么是这个数学工具」，再拆模块：

- 顶层 **2–4 个模块**。每个模块写：功能、输入张量/符号、输出、消费谁的输出。
- 交互：同步还是门控、是否互斥、是否相加、是否只调制幅度。
- 每个模块再拆二级（公式工具）和三级（实现：采样、top-k、clip、归一化）。
- **创新落在哪一层**写死，避免把标准 PPO-clip 说成贡献。
- 同时给：
  - ASCII tree（`|--` / `` `-- ``，避免 Preview 字体缺 Unicode 框线）
  - Mermaid `flowchart`（Preview 出图）

## 问 3 — 算法细节 + 例子配公式

1. 符号表（符号 / 含义 / 来自论文哪一式）。
2. 按训练一个 batch / 一个 token 的顺序重写关键式，用 `$$`。
3. 手算：把维度缩到能算完（2 个 token、G=2 或词表 3）。每步写出数值。
4. 点出 trick：stop-grad、clip、先平均概率再 log、组内 z-score 守卫。
5. 若有伪代码，用 Markdown 有序列表或 `text` 块，关键行用公式编号对照。

## 问 4 — baseline、数据、成本

固定表格列：方法名、是否共享配方、数据规模与划分、模型、GPU 型号×数量、步数、墙钟或 step time。缺则 `[估计]` 并写假设。不要把评测集写成训练集。

## 问 5 — 实验、指标、因果

对主表每一列：

- 指标全称、↑ 还是 ↓、采样次数（avg@32 / pass@1）。
- **因果链**：`实验 A → 数字 X ⇒ 模块 Y 有效`，并标 强/中/弱支撑。
- 消融必须回答「去掉后掉的是不是该模块」。
- 主动写不能支持的：无多种子、peak-checkpoint、baseline 配方更弱。

## 问 6 — 复现准备

Checklist，五项都要有：数据（链接与预处理）、模型权重、硬件最低/推荐、代码入口、算法必做 vs 可延后。再加 3–5 条 sanity（例如 β=0 退回 baseline）。

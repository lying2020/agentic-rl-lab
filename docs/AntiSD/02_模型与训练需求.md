# AntiSD：模型、训练成本、数据集与权重清单

依据：仓库 `README.md` / `recipe/antisd/` / `INSTALL.md`，以及论文 arXiv:2605.11609（HTML v1）Section 4 与 Appendix B Table 5。

---

## 1. 模型架构（不是 CLIP / ViT / 多模态）

本仓库是 **纯文本 Causal LM + RLVR**，没有视觉编码器。

| 角色 | 是什么 | 预训练？ | 微调/训练？ |
|---|---|---|---|
| 学生 \(\pi_S\) | 当前策略 \(\pi_\theta(\cdot\mid x,y_{<t})\) | 必须从开源 Instruct/Think 基座初始化 | **要做 on-policy RL**（AntiSD / SD / GRPO） |
| 教师 \(\pi_T\) | **同一套参数**，条件换成 \((x,c,y_{<t})\) | 不另训 PRM，不另请更强教师 | `teacher_update_rate=1.0`：每步拷贝当前学生（不是慢 EMA） |
| 参考策略 \(\pi_{\mathrm{ref}}\) | 冻结基座 | 论文 Table 5 写了 frozen base | 配置里 `use_kl_loss=False`，KL 系数 0，实际几乎不参与损失 |
| Critic | 无 | GRPO 不用 value head | `algorithm.adv_estimator=grpo` |
| Rollout 引擎 | vLLM | — | 只做采样，不更新 |

论文五模型：

| 模型 | HF ID | 规模 | recipe 脚本 | 上下文设定 |
|---|---|---|---|---|
| Qwen3-8B | `Qwen/Qwen3-8B` | 8B dense | `run/qwen3-8b/` | 16k gen, no-think |
| Qwen3-4B-Instruct-2507 | `Qwen/Qwen3-4B-Instruct-2507` | 4B dense | `run/qwen3-4b/` | 16k gen, no-think |
| Olmo3-7B-IT | `allenai/Olmo-3-7B-Instruct` | 7B dense | `run/olmo3-instruct/` | 16k gen, no-think |
| Olmo3-7B-TK | `allenai/Olmo-3-7B-Think` | 7B thinking | `run/olmo3-think/` | 32k gen, thinking |
| Qwen3-30B-A3B | `Qwen/Qwen3-30B-A3B` | 30B MoE / 3B active | **仓库无脚本** | 论文有表，需自己仿 launcher |

架构族：Qwen3（GQA Transformer）、OLMo-3（开源 dense LM）。**没有 LLaMA / CLIP / ViT。**

AntiSD 不改变模型结构，只改 `grpo_ca` 里的 token 优势。训练结束后权重仍是标准 HF Causal LM。

## 4. 要不要训练？要不要微调？

| 目标 | 要不要训 | 说明 |
|---|---|---|
| 读懂论文 / 画 PMI 热力图 | 可以不训 | 用基座 + 自造 teacher prompt 算 \(u_t=t_t-s_t\) 即可 |
| 单题解题 demo | 可以不训 | 基座 Qwen3-8B 已经能解简单题；AntiSD 增益在 AIME/HMMT |
| 复现 Table 1 / Fig 4 | **必须训** | AntiSD 是 post-training 方法，没有现成 ckpt |
| 从已有 GRPO ckpt 再涨点 | 论文 4.4 continual | `EXTRA_HYDRA_ARGS` 里设 `trainer.resume_mode` / `resume_from_path` |

SFT 不是本仓库主路径（虽有上游 `sft_trainer.yaml`）。

## 5. 论文给出的训练超参（Appendix B Table 5）

| 项 | 值 |
|---|---|
| 优化器 | AdamW |
| 学习率 | \(1\times 10^{-6}\) |
| 步数 | **200** |
| 题 batch | 32 |
| 每题 rollout \(G\) | 8 |
| 训练最大长度 | 32K（全体） |
| 评测最大长度 | 32K；Olmo-Think 64K |
| GRPO clip | 0.2（代码 `clip_ratio_high=0.28`，与表不完全一致） |
| KL 系数 | 0 |
| 训练采样 | T=1.0, top-p=1.0 |
| 评测采样 | T=0.7, top-p=0.95；AIME/HMMT n=32，Minerva n=4 |
| **硬件（论文原话）** | **每节点 8× NVIDIA H20；Qwen3-30B-A3B 多机** |
| 框架 | verl |
| \(\lambda_{\max}\) | 0.5 |
| warmup \(W\) | 5 |
| \(\tau_{\mathrm{down}}\) | \(0.93\cdot H_{\mathrm{warm}}\) |
| 重新打开门 | \(H_{\mathrm{warm}}\) |

代码侧对应：`ca_lambda_max=0.5`，`WARMUP_STEPS=5`，`TP_TARGET_RATIO=0.93`，`REACTIVATE_RATIO=1.07`（用 **teacher perplexity** 近似论文的 teacher entropy，见第 5 篇对照文档）。

启动脚本与论文还有几处不一致，复现时建议改：

| 项 | 论文 | 当前脚本 |
|---|---|---|
| 总步数 | 200 | `total_epochs=1` ≈ 531 step |
| 训练 response | 32K | short launcher **16k**（`max_response_length=16384`） |
| 训练内 val n | 32 | `val_kwargs.n=4` |
| val 温度 | 0.7 | 0.6 |
| Qwen3-30B | 有结果 | 无 run 脚本 |

## 6. 硬件与成本估计

论文 **只写了 8×H20 / node**，没有写墙钟时间和峰值显存。下面按配置反推，属于合理估计，需你用 `nvidia-smi` 再确认。

### 6.1 显存从哪来

同卡上同时存在：

1. **vLLM rollout**（`gpu_memory_utilization=0.55`，`max_model_len=35328` 或 67584）
2. **FSDP Actor** 前向（学生 + no-grad 教师，同一权重；teacher 再 forward 一次）
3. 长序列：16k–32k response × group 8
4. `ppo_micro_batch_size_per_gpu=1`，但 token 仍很长

因此 8B 也不是「一张 24GB 消费卡能训」的规模。

### 6.2 推荐 / 最低 / 论文配置

| 场景 | GPU | 预估 | 说明 |
|---|---|---|---|
| **论文配置** | 8× H20 96GB / 节点 | 8B/7B/4B 单机；30B-A3B 多机 | Table 5 原文 |
| **推荐复现 8B AntiSD** | 8× H20 / H100 / A100-80GB | 与论文同量级 | 保持 batch=32, n=8, 16k |
| **推荐 4B 入门** | 4–8× 80GB | 可先减 `data.train_batch_size` | 4B 最容易复现门控/崩溃现象 |
| **最低能看 loss（不保证数值）** | 2–4× 48–80GB | 必须减小 batch / n / 长度 | 例如 batch=8, n=4, response=4k；**不能**和 Table 1 比 |
| **单卡 24GB（3090/4090）** | 只适合 `inference_math.py` | 训练大概率 OOM | 推理 8B bf16 + 4k token 勉强 |
| **CPU** | — | 只能预处理数据 | 不能训、不宜长生成 |

H20 相对 H100 算力更低、显存更大，更适合 32K 上下文。A100-80GB 能跑，同样长度会更慢。

### 6.3 时间（粗估，非官方）

单步成本大致：32 题 × 8 rollout × 最长 16k，再加学生/教师各一次 logprob。

| 设定 | 粗估墙钟 |
|---|---|
| 8×H20，Qwen3-8B，16k，200 step | **约 1–3 天** 量级（视截断比例） |
| 同样配置跑满 1 epoch（~531 step） | 再乘 ~2.5 |
| Qwen3-4B 同配置 | 略快于 8B |
| Olmo-Think 32k | 明显更慢，脚本把 warmup 加到 10 |
| Qwen3-30B-A3B 多机 | 论文写 multi-node，按 2–4 节点估 |

论文卖点：**AntiSD 用 2–10× 更少的 step 达到 GRPO 精度**（Qwen3-4B 约 10×，Qwen3-8B 约 5×，Olmo-Think 约 2×）。若只关心「追上 GRPO」，4B 可能 ~20 step 就有信号，不必先跑满 200。

### 6.4 论文性能数字（引用）

Table 1 摘录（Avg，下标为 peak-mean step）：

| 模型 | Base | +GRPO | +SD | **+AntiSD** | Speedup |
|---|---|---|---|---|---|
| Qwen3-8B | 22.7 | 57.4@200 | 30.6@200 | **65.7@180** | 5.0× |
| Qwen3-4B-IT-2507 | 47.6 | 51.3@200 | 45.9@10 | **62.8@100** | 10.0× |
| Olmo3-7B-IT | 40.4 | 43.0@190 | 41.1@10 | **48.3@200** | 9.5× |
| Olmo3-7B-TK | 62.0 | 64.1@80 | 62.6@40 | **66.2@40** | 2.0× |
| Qwen3-30B-A3B | 25.5 | 59.1@150 | 34.5@60 | **66.8@140** | 2.9× |

默认 SD 全面弱于 GRPO；Qwen3-4B 的 SD 还会熵崩、长度顶到 32k（Section 4.2）。

## 8. 需要你进一步确认的点

1. 本地是否有论文 latex（`text_xx`）或作者放出的 ckpt / W&B artifact。  
2. 实际 GPU 型号与卡数（决定能不能原样跑 `n=8, batch=32, 16k`）。  
3. 是否要复现 Table 1 的 avg@32（默认脚本是 n=4 + 只测 AIME25）。  
4. 是否要对齐 200 step（需加 `trainer.total_training_steps=200`）。  
5. Qwen3-30B-A3B、代码 RL（Table 2）仓库未提供配方。
